# 案例数字不入库，只留方法与判断

外链、GEO、内容维护都是从公开增长案例和自家数据里归纳出来的做法，但**案例里的流量、收入、引荐域名数、转化率不随仓库分发**：它们属于单个站点在特定时间窗口的结果，换个站、换个词、换个月份就不成立。本页只写"看到什么信号该做什么动作"，以及怎样验证动作真的有效。

## 可以借鉴什么

- 在同一品牌、稳定 URL 和长期需求上积累内容、产品体验与外部推荐。域龄本身不是能证明的直接排名因素；不要把"熬时间"代替需求和质量判断。
- 用产品实际优势决定值得吸引谁。免费入口可以作为获客实验，但要核算单位成本、滥用和转化；别人的免费不限量模式不能直接套给 API 网关。
- 自动化优先承担资料准备、去重、入口核验、状态记录和复查。多 Agent、共享数据库、特定模型或供应商都是案例里的实现方式，不是本地工作流的前提。
- 相关产品的共同引荐来源可以帮助发现合作机会；共同来源不等于允许提交，也不证明链接有效。每个来源还需看实际内容、编辑质量和读者相关性。
- 目录物料保存官网与功能页的真实截图、Logo、核实日期、简介和落地 URL。生成样张不能代替产品界面截图。

## 先用自己的数据选择动作

有 GSC 时：先看项目和站点上下文，复用近 30 天已有研究，避免重复付费查数。GSC 读数优先于第三方流量估算；不同数据库的 rank/DR 不混成同一尺度。

1. 按真实 canonical 主域筛选 GSC 页面和 query+page；域名属性通常包含子域，不能把子产品流量算进主站。记开始/结束日期、国家/设备过滤、是否含未最终数据。先看页面，再看候选页的查询，匿名查询会使查询合计小于页面合计。
2. 找已有展示、排名接近首页、且符合业务的页面。5–20 名与最低展示阈值只是筛选器；小样本、品牌词和无关查询仍要排除。高展示低点击先核对搜索意图、标题摘要、SERP 功能与实际答案位置，不能单凭 CTR 判标题有问题。
3. 先查状态码、重定向链、canonical、noindex 和首屏 HTML。工具说 broken 时分别核对来源页、链接目标和最终地址；200、403/挑战页、404、超时与历史抓取失效分开记。不因一条工具标记删除链接或批量重定向到首页。
4. 候选动作写清页面、证据、机制、主要不确定性和复查日期。优先修已证实访问问题，保护已有流量页，再补实际需求缺口。内容/内链、外部推荐、产品转化分别衡量。

## 外链成果按漏斗记录

用一张母表记录全部机会（配套仓库 [backlink-submission-kit](https://github.com/oiov/backlink-submission-kit) 提供可直接用的模板），不另建竞争队列。新机会保留发现来源、竞品具体落地页、相关性和核验日期，先去重再补入母表。

发现候选 → 资格核验 → 已提交/待审 → 公开上线 → 链接实际存在且目标正确 → 搜索引擎发现/索引（有证据才记）→ 引荐流量/业务结果。

- 成功提示和截图证明已提交，不证明已公开、已索引或传递排名信号。7–14 天可复查待审条目，后续按站方队列调整；查不到索引状态就记未知。
- 记录失败原因、入口与再次核验条件。验证码、手动投稿限制、明确禁止自动化的入口交给人工，不因为换模型而自动重试。
- 衡量相关的独立引荐域、真实来源和有效访问，站点广告位造成的几百条重复链接不等于几百次独立推荐。
- 修正错误品牌资料时准备可核实的品牌和所有权证据。域名注册较早不单独证明商标权；发信、投诉与公开提交仍按用户授权执行。

### 批量提交时的两条硬规则

- **每批限量，稳步推进。** 一次领取几十条就停，跑完看回执和失败原因再领下一批；只投从真实产品站反查出来的高相关来源，不去低质量评论区和论坛签名档刷量。批量越大，越容易把审核队列、限流和账号风险一起招来。
- **截图和凭据分开管。** 提交素材必须是官网首页、定价页、功能页本身的可复用截图，带页面 URL 和日期；登录用的专用邮箱、密码只进密码管理器或 agent 的保险库，不写进数据库、表格和对话记录。

## 不把案例经验变成搜索政策

[Google 垃圾内容政策](https://developers.google.com/search/docs/essentials/spam-policies)明确包含用自动程序或服务为网站制造链接、购买传递排名权重的链接和过度互链等 link spam。站方允许填表并不自动消除搜索政策风险。付费曝光使用适当的 sponsored/nofollow；不把"免费、高 DR、多填表"当成质量认证，不为排名批量制造链接。

[Google AI 搜索说明](https://developers.google.com/search/docs/appearance/ai-features)不要求额外 AI 文件或特殊 schema。GEO 先确保真实内容在 HTML 可读、实体类别一致、证据可核对，再衡量实际引用与访问。

自动化程度还要匹配站点当前权重：内容底子和外部信任都还弱时，极致的自动化会放大风险，排名可能不是慢慢下滑而是一次更新后消失。先把需求和内容做对，再放大效率。

## 衡量增量

- 部署日或公开上线日作为起点，按页记录变更；本地改完不算已发布。
- 用等长且已结束的 28 天窗口比较；新内容先观察 7/14 天发现情况，再看完整窗口。控制主域、国家、设备与品牌词口径；重叠窗口不能当作独立前后实验。
- 同时看非品牌点击、展示、相同查询的排名、引荐访问和可取得的注册/付费。GSC 平均排名不是实时单次位置，展示不是独立用户，第三方估算不是实测访问。
- 固定问题集复测 AI：记录模型/产品、联网开关、问题、日期、引用 URL、品牌提及。AI 引荐访问不等于引用次数，缺失 referrer 也不等于无人引用。
- 外链增长与点击增长同时发生只能支持关联；模型发布、需求季节性、页面更新和算法变化都是可能因素。没有可靠基线就不给增长预测。
