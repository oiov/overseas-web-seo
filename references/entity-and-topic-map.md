# 实体、主题地图与可检索内容

JOKER《近半年 SEO/GEO 认知复盘》整理出的框架。它是经验判断，不是实测数据；Google 官方仍说出现在 AI Overviews/AI Mode 没有额外技术要求，这套东西提高的是被理解、被抽取、被引用的概率，不是新的技术门槛。前置的选词和上站流程不变，见 [find-and-judge.md](find-and-judge.md) 与 [launch-sop.md](launch-sop.md)。

## 一句话

搜索系统每一步都要花资源：抓取、渲染、索引、语义理解、检索、可信度判断。所以它天然偏好"机器理解成本低、信息确定性高"的页面。SEO 的各个分支可以看成各自降低一种不确定性：

| 做法 | 降低哪种不确定性 |
| --- | --- |
| 实体定义 | 你是谁 |
| 主题地图 | 你讲什么 |
| 可检索内容 | 答案在哪 |
| 技术 SEO | 能不能抓到、解析、索引 |
| 站外主题网络 | 你说的话能不能信 |
| 品牌共识 | 不同来源说的是不是同一个东西 |

传统的关键词 + 页面 + 外链 + 技术 SEO 没有失效；这套框架只是在它们上面加了"机器怎么认识你"这一层。SEO 行业每隔一段时间宣布某个东西死了，通常第二年还在做。

## 实体定义：你是谁

在关键词研究之前先固定身份，写清四件事：正式名字、主要类别（一句话）、核心主题、目标用户。落地成站点、社交资料、目录站、媒体稿都能复述的句子，例如 "X is a Y for Z"。

- 首页 title/description、Organization / SoftwareApplication 结构化数据、about 页用同一个类别。
- 一致性是**实体一致**，不是文案一致。同一语义簇里的自然变体没问题："AI-powered SEO platform" / "enterprise SEO automation software" / "SEO automation tool for teams"。
- 真正危险的是跨类别漂移：官网说工具平台，LinkedIn 说营销助理，新闻稿说数据公司，目录写内容写作工具。机器只能继续猜。
- 站外提及要正面且一致；错误描述同样会被 AI 当事实传播，纠正成本比写对高得多。

## 主题地图：你讲什么

- 不是"100 个关键词写 100 篇"。主题地图回答的是这些内容之间的知识关系。
- 结构：实体 → 主题域 → 子主题 → 页面。一个主题域要有入口页，讲清概念、分支和取舍；子页面各回答一个问题并链回入口。
- 选题先问：这篇服务于哪个主题域、和实体是什么关系。答不上来的题目，写多了是在稀释实体，不是在建立权威。
- 覆盖够不够，看问题分解：把用户的一句话问题拆成 5–10 个真实子问题（是什么 / 有哪些 / 怎么选 / 需要什么条件 / 出问题怎么办 / 有什么例子），看站内能不能都找到答案。
- 覆盖要付成本：新站、低权重站不要一次铺满，先入口页加 3–5 个真实子问题，和"新站不批量上页面"一致。

## 可检索内容：答案在哪

AI 检索拿走的常常是一节、一段，不是整篇。要求：

- 一个 H2 一个主题，标题写成用户会问的问题；
- 标题下第一句直接给答案（定义、数字、结论、版本），不先铺垫故事或背景；
- 一节脱离全文仍成立：指代明确，不依赖上一节的"这个方案"；
- 背景、行业回顾单独成节，不要夹在答案和对答案之间；
- 同一事物全文统一叫法；图表带说明，能单独看懂。

自检：把任意一节复制到空白文档，读者还能不能看懂它在回答什么。

## 站外：从外链到主题网络

传统 link building 的指标（DR、相关性、dofollow、锚文字）仍然有效，但在它之后多问四个问题：谁在链接我、那个站属于什么主题、链接周围的句子把我和什么类别连在一起、不同来源是否在强化同一个实体认知。

锚文字不必堆精确匹配词，更有效的是"品牌 + 上下文关系"："X SEO platform"、"X's SEO automation solution"、"X helps enterprise teams automate SEO"。纯品牌锚建立实体，精确匹配锚建立关键词相关性，两种都要有。

来源类型也不必只看行业内容站；目录、社区、媒体、视频、播客、导航页各自贡献不同语境。**提及即可，不一定需要链接**——文字形式的网址和品牌描述同样能被 AI 读到。

## 已有站点：为什么内容不少却没人引用

按顺序查，前一步没解决时改后面几步通常没用：

1. 同一个问题是否被拆成多篇互相抢排名；
2. 名字、类别、产品描述在不同页面和站外是否一致；
3. 主题域有没有入口页，还是只有一堆平行文章；
4. 关键答案是否都埋在中后段，开头在铺垫；
5. 站外提及是否只有链接、没有语义描述；
6. 技术层：canonical、sitemap、参数页、重定向链、内链断裂。

## 边界

- 这套框架解释"为什么同样内容别人更容易被引用"，不承诺排名；选词仍按 Trends、SERP、域名走。
- 不要为了"覆盖实体"写与产品无关的大词扩量，那正是 scaled content abuse 的特征。
- 关于 JS：Googlebot 可以渲染 JS，其他检索客户端的渲染能力与预算各异；关键内容尽量在初始 HTML 可读，并现场核对状态码、robots 和正文。训练抓取、搜索检索和用户触发的访问不是同一个用途，不能把允许某个训练爬虫当作获得 AI 搜索引用的保证。
